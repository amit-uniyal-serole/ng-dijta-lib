## 18.13.1 (2026-05-19)


### 🐞 Bug Fixes

- **release:** strip git name-status output and pretty-format artifacts from rendered commit bodies ([e2d96b9](https://github.com/Serole/ng-dijta/commit/e2d96b9))

  The custom changelog renderer was indenting and emitting two kinds of noise that Nx's getGitDiff includes in the body field passed to renderers:

  1. Per-file change lines (`A\tpath`, `M\tpath`, `D\tpath`, `R\d*\tfrom\tto`, `C\d*\tfrom\tto`) — Nx fetches commits via `git log --pretty=... --name-status` so the file list is concatenated into the body field, and parseGitCommit() extracts those into change.affectedFiles but never strips them from change.body.

  2. Lone-quote artifacts (`"`) on their own line — Nx's --pretty="..." wrapper leaves stray double-quote characters at the start or end of the captured body.

  Renderer now filters both via two additional regex matchers in cleanBody(), and collapses any runs of blank lines that filtering creates so consecutive paragraph breaks don't bloat the entry.

  Also patches the projects/ng-dijta/CHANGELOG.md entry for 18.13.0 — the entry that was generated by the buggy renderer during 18.13.0's release — to replace the messy section with the clean re-rendered output. The matching GitHub Release notes for ng-dijta@18.13.0 were updated via gh release edit. Display-only patch on the 18.13.0 entry; no republish of that version.

## 18.13.0 (2026-05-19)


### 🚀 Features

- **release:** surface commit bodies in changelog and GitHub Release notes ([e86f211](https://github.com/Serole/ng-dijta/commit/e86f211))

  Add a small custom Nx Release changelog renderer that wraps the default renderer and appends each commit's body — verbatim — under its bullet in the generated markdown. Wires it up via nx.json -> release.changelog.projectChangelogs.renderer.

  Why: the default renderer at node_modules/nx/release/changelog-renderer/index.js emits only the commit subject + scope + hash. Contributors who put real explanation in commit bodies (the why, the what-changed, the migration notes) see none of that content in projects/ng-dijta/CHANGELOG.md or in the GitHub Release UI. Release notes for 18.11.0 / 18.11.1 / 18.12.0 showed a single line each despite the underlying commits carrying multi-paragraph bodies.

  What changes:
  - tools/release/changelog-renderer.js (new): ~60-line CommonJS module. Imports Nx's default renderer, calls it, then post-processes the output by matching each bullet on its description line and injecting the body indented two spaces. Strips Co-Authored-By / Signed-off-by trailers (already in Thank You section) and BREAKING CHANGE: lines (already in Breaking Changes section). Commits without a body keep the single-line bullet — purely additive, no regression for terse commits.
  - nx.json: one-line addition pointing release.changelog.projectChangelogs.renderer at the new file via the {workspaceRoot} interpolation.
  - RELEASING.md (new): repo-root guide documenting the release pipeline anatomy, the conventional-commit type → semver mapping, the commit-message convention this renderer depends on, the independent-project file-path gotcha (workflow_dispatch with specifier: patch is the documented escape hatch), and how to edit a published release in an emergency.

  Backfill: projects/ng-dijta/CHANGELOG.md is patched to regenerate the 18.11.0, 18.11.1, and 18.12.0 entries with their full commit bodies using the new renderer. The three corresponding GitHub Releases have been updated via `gh release edit --notes-file ...` to match. No npm artifact is republished — backfill is display-only.

  Also includes doc/explore/library-gaps.md (carried over from a parallel session — append-only gap log for consumer apps to record library shortfalls).



### 📝 Documentation

- **release:** document the commit-body landmine that bumps major unintentionally [skip ci] ([d09d57a](https://github.com/Serole/ng-dijta/commit/d09d57a))

  Add a guarded section to RELEASING.md explaining the conventional-commits marker that Nx scans for in commit bodies, why writing it in prose unintentionally triggers a major bump, and how to mitigate (hyphen / underscore variants, lowercase rephrasing, or the subject-line exclamation marker for genuine breaks). Also captures the Angular-major-aligned versioning rationale so future contributors understand why a wrong major bump is a wrong compatibility claim, not just a semver inconvenience.

  3-step radius scale (--dx-radius-{sm,md,lg}) at :root in
  partials/_default.scss, alongside the existing MD3 color aliases.

  the fallback literals consumer apps already use with var(). No visual

  surface them in the consumer-facing doc/llms.txt brand contract so
  downstream AI agents pick them up automatically.

  Library-internal SCSS migration to consume these tokens (currently raw
  rem/px literals) is intentionally out of scope for this change.
