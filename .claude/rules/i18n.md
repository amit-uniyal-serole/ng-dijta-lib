# Internationalization (i18n) Rules

**Scope:** Transloco 7.5 usage, translation key conventions, and string externalization for the ng-dijta library and the practice app.

---

## Core Requirements

| Requirement | Status |
|-------------|--------|
| All user-facing strings go through Transloco | **MANDATORY** |
| All ARIA labels translatable | **MANDATORY** |
| Pipe syntax preferred in templates | **MANDATORY** |
| No hardcoded user-facing strings | **MANDATORY** |

---

## Transloco Usage (v7.5)

### Pipe Syntax (Templates — Preferred)

```html
<!-- Visible text -->
<span>{{ 'dx.button.save' | transloco }}</span>

<!-- ARIA labels -->
<button [attr.aria-label]="'dx.aria.close' | transloco" mat-icon-button>
  <mat-icon aria-hidden="true">close</mat-icon>
</button>

<!-- With parameters -->
<span>{{ 'dx.items.count' | transloco:{ count: items.length } }}</span>
```

### Structural Directive (Acceptable)

Transloco's `*transloco` directive is a valid pattern in v7.5 and is used in parts of the codebase. Prefer the pipe for small translations; the structural directive is useful when many keys share a template scope:

```html
<ng-container *transloco="let t">
  <button mat-button>{{ t('dx.button.cancel') }}</button>
  <button mat-flat-button>{{ t('dx.button.save') }}</button>
</ng-container>
```

### Component Class Usage

Inject `TranslocoService` for programmatic access:

```typescript
import { TranslocoService } from '@jsverse/transloco';

private readonly transloco = inject(TranslocoService);

saveSucceeded(): string {
  return this.transloco.translate('dx.toast.saveSucceeded');
}
```

> Note: `translateSignal()` is a Transloco 8+ API. This project is on Transloco 7.5 — use `translate()` / `selectTranslate()` instead.

### Forbidden

```html
<!-- FORBIDDEN — Hardcoded visible text -->
<span>No items found.</span>

<!-- FORBIDDEN — Hardcoded ARIA label -->
<button aria-label="Close">...</button>
```

## Translation Key Convention

### Pattern

```
dx.{domain}.{context}.{description}
```

### Examples

| Key | Usage |
|-----|-------|
| `dx.button.save` | Save button label |
| `dx.button.cancel` | Cancel button label |
| `dx.form.error.required` | Required-field validation message |
| `dx.aria.close` | Close button ARIA label |
| `dx.toast.saveSucceeded` | Save success toast |

### Key Rules

- All keys start with `dx.` prefix
- Dot-separated hierarchy
- camelCase for multi-word segments (`primaryAriaLabel`)
- Keys describe intent, not literal content

## Where Translations Live

| Location | Role |
|----------|------|
| `transloco.config.js` | Language and keys-manager config |
| Consumer app's `assets/i18n/{lang}.json` | Translation dictionaries |
| `@jsverse/transloco` `TranslocoModule` / `provideTransloco()` in the app | Runtime configuration |

The **library (`ng-dijta`) does NOT bundle translation files** — it produces keys; the consuming application (`practice` or downstream apps) provides the translations. When adding a new library component that uses translation keys, document the new keys so consumers can add them to their dictionaries.

---

## Supported Languages

Per [transloco.config.js](../../transloco.config.js): currently `en` only. Consumers can configure additional languages (e.g. `ar` for RTL) on their own.

If adding RTL support:
- Use `dir="rtl"` on the document when the active language is RTL
- Prefer logical CSS properties (`margin-inline-start`) over physical (`margin-left`)

---

## Adding New Translation Keys

1. Add the key to the consumer's translation dictionaries (`assets/i18n/en.json` at minimum)
2. Use the `dx.` prefix
3. Reference it via the `transloco` pipe or `*transloco` directive
4. Mirror the key in other language dictionaries the consumer maintains

---

## Checklist

- [ ] No hardcoded user-facing strings in templates
- [ ] No hardcoded ARIA labels
- [ ] `transloco` pipe (or `*transloco` directive) used — no string concatenation with translations
- [ ] Keys follow `dx.{domain}.{context}.{description}` convention
- [ ] Parameters use Transloco interpolation (`{{ 'key' | transloco:{ param: value } }}`)
- [ ] New keys added to every language dictionary the consumer maintains
- [ ] `TranslocoService.translate()` used in component code (not a v8-only API)
